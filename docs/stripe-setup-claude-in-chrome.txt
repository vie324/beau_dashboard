あなたは私のブラウザを操作して、自社サロン管理システム「beau_dashboard」（Next.js / Vercel でホスト）の物販に Stripe 決済をつなぐ設定を行います。
Stripe・Vercel・beau_dashboard の管理画面には、私がこの Chrome でログイン済みです。

# 守ること
- パスワード・2段階認証・本人確認書類・銀行口座の入力が必要になったら、操作を止めて私に任せてください。
- 既存の API キーの「ロール（再発行）」や削除、既存の Webhook の削除はしないでください（他のサービスが止まる恐れがあります）。
- シークレットキー（sk_…）や署名シークレット（whsec_…）の値は、チャットに全文を書かないでください。報告では末尾4文字だけにしてください。
- Stripe の事業者情報・決済手段・明細書表記は、確認して報告するだけにしてください。変更が必要なら、私に確認してから行ってください。
- 画面の文言や配置がこの手順と違っていたら、同じ目的の項目を探してください。見つからなければ、推測で進めずに質問してください。
- Stripe のアカウントや Vercel のプロジェクトが複数あって、どれを使うか分からないときも質問してください。

# 準備：本番ドメインの確認（Vercel）
1. Vercel で beau_dashboard（beau-dashboard と表記されている場合もあります）のプロジェクトを開きます。
2. Settings → Domains で本番ドメインを確認します。独自ドメインがあればそれを、無ければ *.vercel.app のものを使います。以下、これを「本番URL」と呼びます（例: https://example.com 、末尾スラッシュ無し）。
3. Settings → Environment Variables に STRIPE_SECRET_KEY / STRIPE_WEBHOOK_SECRET / NEXT_PUBLIC_APP_URL が既にあるか確認し、あれば適用環境（Production / Preview / Development）を控えます。値は表示しなくて構いません。

# フェーズ1：テストモードで設定して動作確認する
（新しい Stripe アカウントでは、テストモードではなく「サンドボックス」と表示されることがあります。どちらでも同じ扱いです。）

## 1-1. テスト用シークレットキー
- https://dashboard.stripe.com/test/apikeys を開き、「シークレットキー」（sk_test_ で始まる）を表示して控えます。
- 公開可能キー（pk_…）は使いません。制限付きキー（rk_…）も作らないでください。

## 1-2. テスト用 Webhook
- https://dashboard.stripe.com/test/webhooks を開きます（Workbench の「Webhook」または「イベントの送信先」画面になる場合があります）。
- 同じURL（本番URL/api/stripe/webhook）のエンドポイントが既にあれば、新しく作らずにそれを編集し、足りないイベントを追加します。
- 無ければ新しく追加します。
  - イベントの送信元：「お使いのアカウント」（連結アカウントではなく）
  - API バージョン：既定のままで構いません
  - ペイロード形式を選ぶ画面があれば：「スナップショット」
  - 送信先の種類：Webhook エンドポイント
  - エンドポイントURL：本番URL/api/stripe/webhook
  - 説明：beau_dashboard 物販
  - 受け取るイベント（この5つすべて）：
    - checkout.session.completed
    - checkout.session.expired
    - checkout.session.async_payment_succeeded
    - checkout.session.async_payment_failed
    - charge.refunded
- 作成（保存）したら、そのエンドポイントの詳細画面で「署名シークレット」（whsec_ で始まる）を表示して控えます。

## 1-3. Vercel に環境変数を設定する
Vercel のプロジェクト → Settings → Environment Variables で、次の3つを設定します。
既にある変数は新しく追加せず、編集して値を上書きしてください。

| Key | Value | 適用環境 |
|---|---|---|
| STRIPE_SECRET_KEY | 1-1 のシークレットキー | Production（「Sensitive」を有効にする） |
| STRIPE_WEBHOOK_SECRET | 1-2 の署名シークレット | Production（「Sensitive」を有効にする） |
| NEXT_PUBLIC_APP_URL | 本番URL（末尾スラッシュ無し） | Production |

## 1-4. 再デプロイ
- 【ここで一度止まって確認】本番サイトを再デプロイしてよいか私に確認してください。
- 了承を得たら、Deployments で最新の Production デプロイの「…」→「Redeploy」を実行します。「Use existing Build Cache」はオフにします（NEXT_PUBLIC_APP_URL はビルド時に埋め込まれるため）。
- 状態が「Ready」になるまで待ちます。

## 1-5. テスト購入
1. beau_dashboard の管理画面で「物販」（/products）を開きます。上部の「お客様向け販売ページ」カードが「公開中」になっているか確認し、カードに出ているURLを開きます。
   - 「非公開」の場合や、在庫のある商品が1つも無い場合は、止めて私に報告してください。
2. 在庫のある一番安い商品を1つカートに入れ、購入手続きへ進みます。
3. 入力内容：
   - お名前：テスト 太郎
   - メールアドレス：test@example.com
   - 会員番号：入力しない（実在のお客様にポイントが付かないように）
   - 受け取り方法：「店頭で受け取る」
   - クーポン・ポイント：使わない
4. 「決済へ進む」を押して Stripe の決済ページに移動したら、テストカードで支払います。
   - カード番号：4242 4242 4242 4242
   - 有効期限：12/34
   - セキュリティコード：123
   - 名義：TEST TARO
5. 完了ページに戻ったら、注文番号を控えます。
6. 管理画面の「注文」（/orders）を開き、その注文の支払い状態が「決済済」になっているか確認します。反映に時間がかかることがあるので、1分ほど待って再読み込みしてください。
7. Stripe 側の Webhook エンドポイントの詳細画面で、checkout.session.completed の配信が 200 で成功しているか確認します。
8. 確認が終わったら、/orders でテスト注文を「キャンセル」して在庫を戻します。

うまくいかないとき（Stripe 側の配信結果のステータスコードで判断してください）：
- 400（署名検証に失敗）：Vercel の STRIPE_WEBHOOK_SECRET が 1-2 の値と違います。設定し直して再デプロイしてください。
- 404：エンドポイントURLが間違っています。
- 401 / 403：Vercel の Deployment Protection が本番にもかかっています。止めて私に報告してください。
- 500：エラー内容を控えて、止めて私に報告してください。
- 「決済へ進む」を押してもエラーになる：STRIPE_SECRET_KEY が未設定か誤りで、再デプロイも済んでいない可能性があります。

## 1-6. フェーズ1の報告
次の内容を報告して、【止まって】本番モードへ進むか私の指示を待ってください。
- 本番URL
- 作成または編集した Webhook エンドポイント（URL・イベント一覧）
- 設定した環境変数（Key と、値の末尾4文字）
- テスト購入の結果（注文番号・管理画面での支払い状態・Webhook のステータスコード）

# フェーズ2：本番モードに切り替える（私が「進めて」と言ってから）

## 2-1. 本番利用の準備状況を確認する（変更はしない）
- https://dashboard.stripe.com/ を開き、アカウントの有効化（本人確認・事業者情報・入金口座）が完了しているか確認します。未完了なら、何が残っているかを一覧にして止まってください。
- https://dashboard.stripe.com/settings/payment_methods を開き、有効になっている決済手段を報告します。カード以外（コンビニ決済・銀行振込など）を有効にするかは私に質問してください。
- 明細書表記（カード明細に出る店名）の現在の値を報告します。
- 本番URL/shop/（販売ページのスラッグ）/legal を開き、特定商取引法の表記が入っているか確認して報告します。

## 2-2. 本番用シークレットキー
- https://dashboard.stripe.com/apikeys を開きます（テストモードがオフになっていることを確認してください）。
- 「シークレットキーを作成」できる場合は、名前を「beau_dashboard 物販」にして新しく作り、表示された sk_live_ で始まるキーを控えます。このキーは一度しか表示されないので、必ずこの時点で控えてください。
- 作成ができず、既存の標準キーを「表示」できる場合は、それを控えます。
- 「ロール」しか選べない場合は、実行せずに止まって私に確認してください。

## 2-3. 本番用 Webhook
- https://dashboard.stripe.com/webhooks （テストモードがオフの状態）で、1-2 と同じ内容（URL・5つのイベント・スナップショット形式）のエンドポイントを作成するか、既存のものを編集します。
- 本番用の署名シークレット（whsec_…）を控えます。テストモードとは別の値になります。
- テストモードの Webhook エンドポイントは削除せず、そのまま残してください。

## 2-4. Vercel の環境変数を本番用に差し替えて再デプロイ
- 1-3 と同じ手順で、STRIPE_SECRET_KEY と STRIPE_WEBHOOK_SECRET を本番用の値に上書きします（NEXT_PUBLIC_APP_URL はそのまま）。
- 【止まって確認】再デプロイしてよいか私に確認し、了承を得たら 1-4 と同じ手順で Redeploy します（Build Cache はオフ）。

## 2-5. 最終報告
- 本番モードの Webhook エンドポイント（URL・イベント一覧）
- 差し替えた環境変数（Key と、値の末尾4文字）
- 2-1 の確認結果（有効化の状況・決済手段・明細書表記・特商法ページの有無）
- 本番でのテスト購入は行わないでください（実際に請求が発生するため）。必要なら私が行います。
